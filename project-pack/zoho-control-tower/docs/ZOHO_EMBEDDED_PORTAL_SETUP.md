# Zoho Embedded Portal Setup

## What Has Been Built

The workbench links to a separate `/portal/` delivery page with:

- the four ABNAH reference pages;
- reference-first filters, five KPI slots per page and the requested panel
  layout;
- synthetic acceptance values in Blueprint mode;
- a Live Zoho mode for one secured dashboard embed per page;
- one-file JSON import/export plus browser-local URL storage so work-laptop
  embed URLs do not need to be committed;
- explicit placeholders for the action queue and exact consumption waterfall
  that may later require custom rendering.

The committed configuration is:

```text
config/zoho-portal.json
```

The transferable blank handoff file is:

```text
config/zoho-secured-embed-handoff.example.json
```

It contains report names, source Query Tables, fields and blank embed URLs. It
contains no operational rows, OAuth token, password, client secret or private
permalink.

## Security Decision For The MVP

Use:

```text
Public/static shell + Zoho secured-login dashboard embeds
```

The GitHub Pages shell can be opened by anyone who knows its URL, but the
embedded data remains inaccessible unless the viewer:

1. signs in to Zoho; and
2. is a user with whom the dashboard was shared.

Share the four dashboard views only with the exact registered company email
that should have access. This meets the immediate single-user requirement for
the data views.

Do not use:

- Public Access;
- Access without Login;
- a private permalink;
- a client-side OAuth access or refresh token;
- a client secret in JSON, JavaScript, GitHub Pages or SharePoint markup.

GitHub Pages is static. It cannot securely hold a Zoho client secret, mint
short-lived embed URLs, or enforce a private company-email allowlist for the
outer shell.

## Part 1 - Prepare Four Zoho Dashboard Views

Create or retain one Zoho dashboard tab/view for each page:

1. `CT_PAGE_1_Risk_Action_Center`
2. `CT_PAGE_2_Procurement_Vendor_Capital`
3. `CT_PAGE_3_Consumption_Menu_Profitability`
4. `CT_PAGE_4_SCM_Explorer_Data_Quality`

Inside each view:

1. Place the five reference KPI objects first.
2. Place the reference views in the order specified in
   `ZOHO_CURRENT_WORKSPACE_MIGRATION.md`.
3. Add the native Zoho user filters from the dashboard build guide.
4. Customize each report's filter mapping.
5. Save and test the dashboard in View Mode.
6. Set the default current period to `month_03`.
7. Confirm historical charts still retain all three months.

For the first release, filters remain inside the Zoho dashboard embed. This is
more reliable than trying to make one external URL criterion map automatically
across unrelated physical Query Tables.

## Part 2 - Restrict Each Dashboard To The Work Email

Repeat for each page dashboard:

1. Open the dashboard in Zoho Analytics.
2. Choose **Share**.
3. Share it with the exact registered company work email.
4. Assign Viewer/read-only access.
5. Remove every unintended user, public access rule and old without-login
   share.
6. Open **Share > Embed**.
7. Choose the secured/with-login access option.
8. Confirm the secured view works after signing out and signing back in with
   the work account.

For stricter row-level control, the workspace administrator can also use a
sharing criterion or custom variable based on `System.login.email`. Sharing to
one Viewer is sufficient for the current single-account MVP.

## Part 3 - Copy The Correct URL

For each secured embed:

1. Copy the iframe generated by Zoho.
2. From the iframe, copy only the `src` URL.
3. Confirm the host is an HTTPS Zoho Analytics host, for example
   `analytics.zoho.in`.
4. Do not copy an Access without Login or Public URL.

The committed JSON intentionally leaves every `dashboardEmbedUrl` blank.

## Part 4 - Connect The Four URLs Without Editing Code

On the work laptop:

1. Open the published workbench.
2. Choose **Live portal**. It opens as a separate page rather than an Atlas
   tab.
3. Choose **Configure**.
4. Either paste one secured Zoho iframe `src` into each page field and choose
   **Save locally**, or choose **Import** and select the four-dashboard handoff
   JSON.
5. Use **Handoff** to export the current four URLs for another approved browser
   profile.
6. Open each page and switch from **Blueprint** to **Live Zoho**.
7. Complete the Zoho sign-in prompt with the registered work account.

The four URLs are stored in that browser's local storage. They are not pushed
to GitHub and will not appear on another laptop or browser profile.

The JSON file contains secured iframe URLs, not passwords or OAuth
credentials. Never add a token, client secret or operational report row.

To make URLs part of a controlled internal build instead, place the secured
login URLs into each page's `dashboardEmbedUrl` in
`config/zoho-portal.json`, rebuild, and deploy. A secured-login URL is still
protected by Zoho sharing, but committing view identifiers is less private than
browser-local configuration.

## Part 5 - How Updates Reach The Site

Zoho states that embedded users see the latest live version and report changes
are reflected in the embed. Therefore:

- saving a Zoho report/dashboard updates the embedded view;
- refreshing or reopening the portal loads the current Zoho version;
- the portal does not copy or cache ABNAH rows;
- a full site rebuild is not required when only the Zoho report design or data
  refresh changes;
- a site rebuild is required when navigation, layout, report names or portal
  configuration changes.

## Filter Strategy

### MVP: native dashboard filters

Keep `filterStrategy` as:

```json
"filterStrategy": "native_dashboard"
```

The Live Zoho iframe owns its filters. Configure those filters inside Zoho and
map them per report. Blueprint mode shows the intended external layout but does
not calculate filtered values.

### Advanced: one embedded view per slot

Use per-slot embeds only when the reference shell must own every filter and
panel. Each view needs its own table/column mapping. Append a URL-encoded
`ZOHO_CRITERIA` value:

```text
("27_fact_ct_inventory_risk.sql"."source_period_code" = 'month_03')
AND
("27_fact_ct_inventory_risk.sql"."outlet_code" = 'OUT001')
```

The generalized browser operation is:

```javascript
const url = new URL(securedEmbedUrl);
url.searchParams.set("ZOHO_CRITERIA", criteria);
iframe.src = url.toString();
```

Do not reuse a Query 27 table-qualified condition against a Query 28 or Query
33 view. Every slot must use the table and column names that exist in that
view. Validate the filtered total in Zoho before enabling the external control.

Zoho supports `=`, `!=`, `<`, `>`, `<=`, `>=`, `LIKE`, `IN`, `BETWEEN` and
combined `AND`/`OR` criteria. String values use single quotes; table/column
names use double quotes; the complete expression must be URL encoded.

## Exact Custom-Visual Fallbacks

### Consumption bridge

MVP:

- embed `CT_P3_Consumption_Bridge` as a Zoho Combination chart;
- use the Query 20 signed bridge fields;
- require one canonical UOM for quantity mode.

Exact later version:

1. expose an approved aggregated bridge endpoint from a server;
2. request opening, purchase, transfer-in, signed transfer-out, signed return,
   signed closing and actual consumption values;
3. render a client waterfall;
4. reconcile its final total to Query 20 before publication.

### Priority action queue

MVP:

- embed the sorted `CT_P1_Action_Center` tabular report.

Exact later version:

1. request approved Query 27 action rows from a server endpoint;
2. render the reference card queue;
3. open a detail drawer on selection;
4. preserve the Zoho report link for export and underlying-data audit.

No custom browser component may calculate stockout, expiry, OTIF, leakage or
margin logic independently.

## OAuth And Short-Lived Embed URLs

Zoho's Embed URL API can generate a short-lived URL with criteria and
permissions, but it is documented for Embedded Analytics customers. It
requires:

- a server;
- an organization ID, workspace ID and view ID;
- OAuth scope `ZohoAnalytics.embed.read`;
- a client ID, client secret and refresh token held server-side;
- an entitlement check for the ABNAH/ABG Zoho plan.

This is a production option, not the GitHub Pages MVP. When enabled, add a
server endpoint that verifies the allowed work email, requests the short-lived
URL and returns only that URL to the browser.

## Hosting Choices

### GitHub Pages

Best for the present shell:

- transferable through Git;
- no operational data in the repository;
- secured Zoho views remain protected by Zoho sign-in;
- browser-local embed configuration works on the work laptop.

Limitation: the shell itself is public.

### Localhost

Use the repository's normal development command. It provides the same portal
and browser-local configuration without publishing the shell.

### SharePoint

SharePoint can provide an organization/Entra access gate around a page, but
custom scripts and iframes may require tenant-approved SPFx or embed-domain
configuration. Its standard Embed web part does not become a Zoho API backend
and does not allow arbitrary custom script. Confirm policy and allowlist
`analytics.zoho.in` with the Microsoft 365 administrator before moving the
shell.

### Production server or protected static host

Use this when the entire shell must be company-email-only. Enforce the
allowlist server-side, keep Zoho secrets in environment variables, restrict
embed origins/domains, and generate short-lived URLs if the Zoho entitlement
supports it.

## Troubleshooting

### Zoho sign-in loops inside the iframe

1. Sign in to `https://analytics.zoho.in/` in a normal tab.
2. Reload the portal.
3. Confirm browser third-party-cookie policy allows the Zoho session.
4. Confirm the dashboard was shared to the same email.

### The iframe says access denied

The URL is valid but the signed-in Zoho user does not have access. Correct the
dashboard sharing list; do not replace it with an without-login link.

### A saved URL disappears

Browser-local URLs are profile-specific and can be cleared with site data. Add
them again through **Configure > Import** using the one-file handoff.

### Filters do not affect every report

Return to the Zoho dashboard editor and customize the filter mapping for each
report. Do not solve a native dashboard mapping problem by adding an
unvalidated external `ZOHO_CRITERIA`.
