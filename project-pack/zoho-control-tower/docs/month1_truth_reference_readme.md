Correct definition:

```text
1 only when po_status is Pending / Partially Received, or remaining_qty > 0
```

## Vendor And Procurement Truth

Use these rules in the demo and in Zoho setup:

- `PO Raised Value` means purchase order line value from `purchase_report.total_item_cost`.
- `Receipt Booked Value` means goods/entry receipt value from `entry_report.grand_total`.
- `PO Raised Value` can be higher than `Receipt Booked Value` even when `Open / Partial PO Status Count` is zero. That means there is a value gap in the selected period, not necessarily an open-status PO.
- Receipt rows do not carry `po_number` or `po_status`. Because of that, `PO Status` should be mapped only to PO status visuals and the open/partial KPI, not to receipt booked value.
- If you want a card that explains the gap, add `PO vs Receipt Value Gap = SUM(ordered_value) - SUM(received_value)`.

## Filter Architecture To Use In Zoho

| Dashboard | Primary table | Filter order | Mapping rule |
| --- | --- | --- | --- |
| 01 Executive Outlet Health | FACT_Outlet_Daily_Health | Outlet -> Date Range -> Event Type | Outlet maps to outlet_name; Date Range maps to activity_date. Event Type maps only to event tables. |
| 02 Sales Menu Intelligence | FACT_Sales | Outlet -> Sales Date -> Super Category -> Category -> Menu Item | Build category mix and date-sensitive top items from FACT_Sales. Summary item tables are not date-safe. |
| 03 Vendor Procurement Analytics | FACT_Vendor_Spend | Outlet -> Procurement Date -> Vendor -> Material -> Category; PO Status separate | Outlet/date/vendor/material apply to PO and receipt cards. PO Status applies only to PO status/open-count visuals. |
| 04 Inventory Consumption Intelligence | FACT_Inventory_Closing for date charts; SUM_Inventory_Risk for latest snapshot | Outlet -> Inventory Date -> Category -> Inventory Item -> Pressure Band | Do not expect SUM_Inventory_Risk to respond to historical inventory date ranges. |
| 05 Calendar Event Competitor Intelligence | SUM_Event_Impact, SUM_Event_Markers, SUM_Competitor_Positioning | Outlet/Market -> Event Type -> Competitor Category -> Price Position -> Item | Event and competitor data are contextual. Use market_area for competitor filters. |

Zoho build rule for cascading filters:

1. Create the broadest dropdown first from the dashboard primary table.
2. Create narrow dropdowns from the same primary table when possible.
3. Enable `List only relevant values` for each dropdown.
4. If a widget does not change, open the widget and map the dashboard filter to that widget source table's own field.
5. Do not rely on `DIM_*` filters until direct source-table filters work.

## Dashboard Source Corrections

| Issue | Cause | Fix |
| --- | --- | --- |
| Category revenue mix does not change with date filters | Built from SUM_Sales_Category_Mix or unmapped filter | Rebuild from FACT_Sales: X category, Y SUM(net_sale), filters outlet_name, sales_date, category, super_category. |
| Menu item detail repeats entities | The table has outlet + item grain or a raw/detail table is being viewed without grouping | Use outlet filter or create Summary/Pivot View grouped by item_number, item_name. Use FACT_Sales if date filter must work. |

| Open/partial count is zero while PO raised value exceeds receipt value | Open count is status-based, while value gap is value-based | Add separate PO vs Receipt Value Gap KPI. Keep open/partial status count as a status-control KPI. |
| Revenue per inventory rupee adds across outlets | Zoho is summing outlet-level ratio values | Use aggregate formula SUM(net_sales) * DISTINCTCOUNT(activity_date) / SUM(inventory_value). |

## Final Rules For Demo Confidence

- Start every dashboard QA from the source table grain, not the visual label.
- Date filters only work when the visual source table has a compatible date field.
- Cascading filters work best when all dropdown values come from the same dashboard primary fact table.
- Ratios must be aggregate formulas. Never sum an already-calculated ratio across outlets.
- PO value, receipt value, and open status answer different questions. Keep them as separate KPIs.
- The synthetic story is deterministic. If Zoho disagrees with these numbers for Month 1, the issue is table grain, filter mapping, refresh state, or chart aggregation.
